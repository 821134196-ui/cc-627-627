# 试吃样品与过敏告知系统

门店发放试吃样品时，用于登记原料批次、打印过敏原告知牌、巡查核对、发放记录与批次召回追溯。

## 一条命令启动

```bash
npm start
```

- 首次启动会自动安装前后端依赖、创建 SQLite 数据库（`server/prisma/app.db`）并写入演示数据
- 前端：http://localhost:5173
- 后端 API：http://localhost:3001/api

## 运行规则测试（打印失败/超时阻止发放、换批次重新核对、发放记录追溯）

```bash
npm test
```

## 业务规则

1. 制作人登记原料批次、制作时间、发放截止时间，生成并**打印过敏原告知牌**
2. 巡查员核对告知牌与实物一致、记录巡查经手人后，样品才**可以发放**
3. **打印失败、样品到期、过敏原标错**：立即停止发放（终态，不可恢复）
4. **更换原料批次必须新建样品**，不能在旧样品上改批次，也不能沿用旧告知牌
5. 停止后已发出的发放记录继续保留；**批次召回**时按原料批次 → 样品 → 发放记录逐层追查
6. 仅修改标签文字不能让样品恢复发放——停止是终态，恢复供应只能重新制作、重新打印、重新核对

## 工作台分区

- **待核对**：已登记，等待打印告知牌 / 等待巡查核对
- **可以发放**：核对通过且未到发放截止时间
- **已停止**：打印失败 / 已到期 / 过敏原标错 / 批次召回

## 技术栈

- 后端：TypeScript + NestJS + Prisma + SQLite（端口 3001）
- 前端：React + Vite + TypeScript（端口 5173）
- 打印与召回通知均为本地模拟（服务端控制台 + 站内通知中心）
